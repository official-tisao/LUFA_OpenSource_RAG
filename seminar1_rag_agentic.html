Slide 2

The Problem with LLMs Alone

  • LLMs have a fixed knowledge cutoff
  • They hallucinate confidently in domain-specific queries
  • No citations, no verifiability
  • Especially dangerous in Contract / agreement contexts

⚠️ Hallucination Example

User asks ChatGPT about a collective agreement clause:

Q: "What is Article 15.3 of the LUFA agreement?"
A: "Article 15.3 states that faculty are entitled
to 30 days annual leave with full pay..."

❌ This clause does not exist.

LLMs are trained on general web data. They have no access to your institution's private documents.

How RAG Works Technically

  • Text → Chunks → Embeddings → Vector Store
  • At query time: embed query → similarity search → retrieve top-K
  • Feed chunks + query to LLM as context
doc.txt → chunks(1024 tokens)
chunk → embed() → [0.23,-0.11,...]
vectors → ChromaDB.store()

# At query time:

Slide 5

Limitations of Standard RAG

❌ Single-Shot

One query → one retrieval → one answer. No iteration. No second chance if retrieval is poor.

❌ Fails on Vague Queries

"What about the salary?" too vague. Standard RAG retrieves random chunks with no refinement.

❌ No Self-Correction

If retrieval returns irrelevant chunks, the LLM still generates an answer, just a bad one.

❌ No Memory Across Turns

Each query is independent. Cannot answer follow-ups like "And what about part-time faculty?"

⚡

Standard RAG is a fixed, one-pass pipeline. Works for simple queries, breaks in real-world contract/agreement retrieval where questions are nuanced and multi-part.

Slide 6

Enter Agentic RAG

Adding a "brain", dynamic, self-correcting, multi-step

🔄 Query Rewriter

  • "salary?" → "What is the 2024 faculty salary grid per rank?"
  • Rephrases vague queries for precision

🎯 Retrieval Evaluator

  • Grades retrieved chunks: relevant or not?
  • Triggers re-retrieval if score is low

🪞 Self-Reflection

  • "Is this answer grounded in retrieved text?"
  • Prevents hallucination by verifying sources

🔁 Re-retrieval Loop

  • If reflection fails → search again
  • Iterates until answer is trustworthy
💡

The agent decides dynamically how many retrieval steps are needed, not hardcoded like standard RAG
